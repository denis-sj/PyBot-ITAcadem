# Эвалы агента

Эвалы используют тот же `AgentService`, prompt, реестр инструментов и проверки прав,
что runtime. Чтения заменены детерминированными фикстурами; действия — моками.
Раннер не подключается к базе данных, Telegram или рабочей группе. Каждый кейс
использует синтетического автора и синтетических получателей.

Запуск — платный и только по явной команде:

```bash
uv run python -m evals.agent.run --model deepseek/deepseek-v4.1-flash --repeat 3 \
  --report evals/agent/reports/baseline.json
```

Можно ограничить прогон кейсом через повторяемый `--case NAME`. `--repeat` принимает
от 1 до 3. Нужен `POLZA_API_KEY`; раннер читает настройки обычным `get_settings()` и
не показывает секреты. Целевой slug зафиксирован. Тарифы берутся из проверенного каталога
`reports/provider-catalog.json`: при неизвестном provider используются максимальные
цены модели для входа и выхода; цена кэша применяется при известном provider.
Точный `cost_rub` приоритетнее любых оценок.

До запуска раннер показывает верхнюю оценку для числа кейсов, повторов,
`AGENT_MAX_STEPS`, входа и генерации. Перед каждым API-вызовом он проверяет размер
сообщений и схем инструментов через `cl100k_base` с двукратным запасом и резервирует
двойную оценку фактического входа (не более 32 000 токенов) и установленный
лимит выходных токенов по максимальным тарифам проверенного каталога.
Общий потолок — 40 ₽ (разрешено пользователем 14.10.2026); новые вызовы
останавливаются, если резерв уже не помещается в остаток. Стоимость ответа берётся
из `cost_rub` (адаптер также читает `cost`).
Если цена отсутствует, используются usage и тарифы выше; кэш без отдельного тарифа
учитывается как обычный вход. Если usage нет, применяется верхняя оценка по
двойному proxy-подсчёту входа и полному `max_tokens`. Записи помечаются
`estimated=true`; отчёт содержит количества оценочных и точных записей ledger.
Первый неудачный запрос оценён в 1 ₽ по явному указанию пользователя.
Скрытые повторные попытки SDK отключены для прозрачного учёта каждого вызова.
Ledger содержит накопленную сумму и записи стоимости без содержимого запросов.

JSON-отчёт включает агрегаты по стоимости, токенам, кэшу, времени, точности выбора
инструментов и аргументов, подтверждениям и категориям ошибок безопасности. Он не
содержит вопросы, ответы, аргументы инструментов или идентификаторы получателей.
Размер инструкции и схем инструментов считается локально через `cl100k_base` как
оценка: это не токенизатор DeepSeek и не точный подсчёт служебной структуры API.


## Диагностика provider

`uv run python -m evals.agent.provider_matrix` отправляет один синтетический вопрос
без инструментов, с простым инструментом, со схемами Student и Admin; инструменты
не выполняются. По два запроса на сочетание режима reasoning и маршрута.
`--route`, `--tools`, `--omit-parallel` ограничивают диагностический прогон.
Результаты сохраняются после каждого запроса в JSON и Markdown. Ошибки Polza
записываются с удалением API-ключа и bearer-токенов. В диагностике max_tokens=300,
автоматических повторов нет; это проверка совместимости, а не baseline качества.
Общий лимит всех платных прогонов — 40 ₽ (новое разрешение пользователя 14.10.2026).
Исторические оценки сбоев пересчитаны по максимальным тарифам каталога; исходные
оценки сохранены в ledger для аудита.

Агрегаты записываются атомарно после каждого кейса и при отмене прогона.
При первом HTTP 429 раннер сохраняет отчёт и останавливает новые запросы;
ошибка не повторяется автоматически. `run_cost_rub` включает все записи ledger
этого прогона, включая прерванный запрос, а `completed_question_cost_rub` —
стоимость завершённых кейсов. В незавершённом отчёте `aborted=true`; такой отчёт
не заменяет требуемое полное сравнение качества.

## Учёт ошибок без usage и причины провалов

Если ответ не содержит usage (HTTP-ошибка, timeout или отмена), ledger резервирует
верхнюю оценку по размеру запроса, полному `max_tokens` и тарифу исполнителя. При
неизвестном исполнителе используется максимальный тариф модели. Такая консервативная
оценка соблюдает пользовательский лимит; предположения о том, списывает ли Polza
деньги за отдельные классы ошибок, её не заменяют. Запись помечается
`estimated=true` с источником `request_error_upper_bound`.

Для каждого кейса отчёт содержит `failure_reasons`: ожидаемый и фактический набор
инструментов, отсутствующие фразы, неверные аргументы и статус ответа. Текст ответов
модели в отчёт не попадает. При провале причины печатаются в консоль строкой `reason:`.
